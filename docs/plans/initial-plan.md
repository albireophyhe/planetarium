# Planetarium 初期実装計画

- 作成日: 2026-07-29
- 状態: 置換済み（ユーザーストーリーレビュー後は`revised-plan.md`を正本とする）
- 対象: macOSネイティブ版、Cloudflareへデプロイ可能なWeb版

## 1. 目標

利用者が場所と時刻を選ぶだけで、その時に見える主要な恒星・星座・方角を直感的に確認できることを最初の完成条件とします。専門知識がなくても操作でき、詳しい利用者には計算条件が分かり、開発者には再現可能な構成であることを重視します。

## 2. MVPの機能

### 星空

- 現在時刻と選択地点から見える主要恒星を全天表示する。
- 地平線、天頂、東西南北、星の明るさを読み取れる。
- ドラッグで方角、ホイール／ピンチで視野角を変更する。
- 主要な星座線と星座名を表示・非表示にする。
- 星を選ぶと名称、等級、距離、赤経・赤緯、高度・方位角を表示する。

### 時刻と場所

- 「いま」に戻る操作を常に見つけられる。
- 時刻スライダーと再生／停止で星空の移動を確認できる。
- 初期地点は東京とし、緯度・経度の手入力を可能にする。
- Webの位置情報は明示操作の後だけ要求し、拒否されても利用可能にする。

### 学びやすさと安全性

- 初回に三つ以内の短い操作ヒントを表示し、再表示できる。
- 色だけに依存しない選択状態、キーボード操作、読み上げ用ラベルを用意する。
- 位置は既定で端末外へ送信せず、保存する場合も利用者が解除できる。

## 3. MVPの対象外

- 写実的な天の川、星雲画像、望遠鏡制御
- 人工衛星、流星群通知、気象・雲量
- 高精度な惑星暦、日食・月食予報
- アカウント、同期、ソーシャル共有
- 外部APIがなければ動かない機能

対象外の項目は、ユーザーストーリーレビューで優先度が変わった場合のみ再検討します。

## 4. 構成

```text
.
├── apps/
│   ├── macos/                 # SwiftPM + SwiftUI
│   └── web/                   # React + TypeScript + Vite
├── shared/
│   ├── catalog/               # 恒星・星座JSONと出典
│   ├── schema/                # JSON Schema
│   └── fixtures/              # 座標変換の共有期待値
├── docs/
│   ├── decisions/
│   ├── plans/
│   ├── product/
│   └── progress/
├── script/                    # ルート検証、Mac build/run
└── .github/workflows/         # 両版のCI
```

WebはCloudflare ViteプラグインとWorkers Static Assetsを使い、SPAの不明なパスは`index.html`へ戻します。macOSはアプリ全体の状態を一つの観測可能なストアが所有し、描画、操作パネル、選択した天体の詳細を小さなViewへ分けます。

## 5. データと計算

- 恒星はMVPで肉眼観測向けの明るい星を中心に、名称、別名、赤経、赤緯、見かけの等級、距離、色指標、所属星座を保持する。
- 星座線は恒星IDの組で保持する。
- UTC日時、観測地点、恒星の赤経・赤緯から、ユリウス日、恒星時、時角、高度・方位角を求める。
- 地平座標を方位角等距離図法で画面へ投影する。
- 共有フィクスチャは、東京・シドニー・レイキャビク、現在・季節の代表日時・日付変更付近を含める。
- MVPの精度目標は、共有フィクスチャに対し高度・方位角の差を0.2度以内とする。採用する星表の元期と簡略化を画面または文書で明示する。

## 6. 実装フェーズ

### Phase A: リポジトリ基盤

- ルート文書、編集規約、無視設定、Node 22指定を追加する。
- Web／macOS／共有データのディレクトリと最小ビルドを作る。
- ルートからlint、test、buildを実行できるようにする。
- GitHub ActionsでWebとSwiftを独立して検証する。

### Phase B: 共有仕様と計算

- JSON Schema、最小星表、星座線、出典メタデータを追加する。
- TypeScriptとSwiftで座標変換・投影を実装する。
- 共有テストベクトルを両版で検証する。

### Phase C: Web版

- 完成画面のビジュアル仕様とデザイントークンを確定する。
- 星空Canvas、時刻、場所、レイヤー、選択詳細を実装する。
- キーボード、レスポンシブ、位置情報の許諾・拒否フローを実装する。
- Viteビルド、Cloudflareローカルプレビュー、ブラウザ操作を検証する。

### Phase D: macOS版

- `WindowGroup`のメインウインドウ、ツールバー、設定画面、メニューコマンドを作る。
- Webと同じ情報階層を、ネイティブのサイドバー／インスペクタへ適応する。
- SwiftPMの`.app`生成とCodex Runボタンを構成する。
- ビルド、ユニットテスト、起動確認、キーボード操作を検証する。

### Phase E: 統合品質

- 同じ日時・地点・恒星に対する両版の結果を比較する。
- README、制約、データ出典、プライバシー説明を完成させる。
- 表示性能、狭い画面、VoiceOver相当のラベル、エラー状態を確認する。

## 7. ユーザーストーリーレビュー

初期計画を固定した後、少なくとも次の視点からストーリーを作ります。

- 開発者／保守者
- 初めて使う一般利用者
- 観望前に確認したい利用者
- 天文学に詳しい利用者
- 教育者・学習者
- アクセシビリティ要件のある利用者
- このアプリに関心がない、または偶然開いた人
- プライバシーや通信量を気にする人

各ストーリーは「価値」「頻度」「失敗時の影響」「実装コスト」「MVPとの整合」で評価し、Must／Should／Could／Won'tへ分類します。分類後、この文書とは別に改訂計画を作り、実装の正本を切り替えます。

## 8. 完了条件

- Web版とmacOS版がクリーン環境でビルド・テストできる。
- 指定地点・時刻で星空が表示され、選択、時刻変更、場所変更、表示切替が実際に状態を更新する。
- 共有座標テストが両版で許容誤差内に入る。
- Webはデスクトップとモバイル相当の表示で、重大なコンソールエラーや欠けがない。
- macOSは生成したアプリバンドルを起動できる。
- データ出典、精度上の制約、位置情報の扱いを利用者が確認できる。

## 9. 改善ループ

初回完成後、各ループを「観察→優先度決定→一つの改善→回帰検証→記録」とします。機能、天文学的妥当性、アクセシビリティ、性能、見た目、ドキュメントを偏りなく扱います。

停止条件は、改善ループ50回完了またはこのゴールの累計実行時間16時間超過の早い方です。停止時には、実施回数、各変更、検証結果、残る候補を`docs/progress/iterations.md`へ残します。

## 10. 主なリスク

- 星表のライセンスと出典: 再配布可能性を確認し、出典メタデータを同梱する。
- 二重実装の差: 共有フィクスチャと許容誤差で検出する。
- Canvasのアクセシビリティ: 操作可能な天体一覧と読み上げ用のDOM／SwiftUI要素を別に提供する。
- 現在のローカルNode 21はViteの推奨範囲外: Node 22 LTSをリポジトリ標準とし、CIでも固定する。
- 機能過多: 「いま・ここで見える星空」を最優先にし、MVP対象外を守る。
