# ADR 0001: 二つのネイティブ描画実装と共有データ契約を採用する

- 状態: 暫定採用
- 日付: 2026-07-29

## 背景

macOS版には純正らしい操作感、Web版にはインストール不要の到達性とCloudflareへの単純なデプロイが必要です。一方で、星表、星座、時刻・位置からの座標変換が版ごとに食い違うことは避けなければなりません。

## 判断

- macOS版はSwiftUI Canvas、Web版はReactとHTML Canvasで描画する。
- UIコードと描画コードを無理に共有しない。
- 星表、星座線、天文計算の仕様、期待値を持つテストベクトルはJSONで共有する。
- 赤経・赤緯から高度・方位角への変換は両言語で小さく実装し、同一ケースで一致を検証する。
- 外部天文APIはMVPの必須依存にしない。

## 理由

WebビューをMacアプリに包む方式よりも、SwiftUIはメニュー、キーボード、アクセシビリティ、ウインドウ管理を自然に実現できます。計算コードをWebAssemblyなどへ共通化する方式よりも、少数の十分に説明可能な式と共有テスト値を採用した方が、初期のビルド複雑性と障害点を減らせます。

## 影響

- 二つの計算実装を保守するコストが生じる。
- 共有フィクスチャと許容誤差のテストを必須にして差異を検出する。
- 高精度な歳差、章動、固有運動、惑星暦は、MVP後に精度要件とともに別ADRで検討する。
