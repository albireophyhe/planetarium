# ユーザーストーリーと優先度

- 評価日: 2026-07-29
- 対象: `docs/plans/initial-plan.md`
- 判定方法: 価値、利用頻度、失敗時の影響、実装コスト、MVPの中心価値を総合したMoSCoW

## 最優先の発見

初期計画は二つのクライアントと共有天文仕様の骨格は妥当でしたが、次の点が不足していました。

1. 「幾何学的に地平線上」と「肉眼で見える」を分ける説明。
2. 太陽高度による昼・薄明・夜の表示。
3. 日付、時刻、観測地点のタイムゾーンを一体で扱うモデル。
4. 緯度経度を知らない人向けの都市プリセット。
5. Canvasを直接操作できない人にも使える検索可能な天体一覧。
6. 東西、北、投影法、リセット後の向きの明文化。
7. 天頂付近でも意味を失わない角距離による精度評価。
8. 位置権限拒否、データ破損、描画不可を含む復旧可能なエラー状態。
9. 初期転送量と連続描画の性能予算。

## Won't（このMVP）

- 天候・雲量、光害推定、遮蔽物を含む可視性予測
- 望遠鏡制御、人工衛星、彗星、小惑星、流星群通知
- アカウント、クラウド同期、ソーシャル共有
- 高精度な食予報、AR表示

## 優先順位の変更

- 日付・時刻の直接入力を、自動再生より先に実装する。
- 太陽高度と薄明を高精度惑星暦から切り離してMustにする。
- 距離、赤経、赤緯は初期詳細の前面から「詳しい情報」へ移す。
- 初回ヒントと専用設定画面は、画面自体の理解しやすさが確認できた後にする。
- 月はShould、肉眼惑星はCouldのままにする。
- Canvasと同じ状態を操作できる検索・一覧を、補助機能ではなく中心機能として扱う。

## 現行コード再監査

- G1・I2・N1: Webの空の`#root`を静的boot shellへ置き換え、
  「場所と日時の星空を表示するアプリ」「東京・現在時刻を準備中」を
  React起動前から表示する。styleはCSPに従う同一originの`boot-shell.css`へ分け、
  JavaScript無効時は必要条件と同一originの再読み込み導線へ置換する。
  第三者通信を増やさず、成果物検査とReact置換の実ブラウザー確認を完了した。
- O3: 初回の簡易太陽式は第2フェーズで置き換え、恒星と同じ地球姿勢・時刻系を使う
  太陽中心の幾何高度と、2D・3Dの方向マーカーまで実装した。
- A1: `UTC≈UT1`という初回MVPの近似は現行v2の既定ではなく、
  UTC・TAI・TT・UT1、同梱IERS EOP、共有VSOP2000由来100項地球暦を分離する。
  詳細な現行契約は`user-stories-phase2.md`を正本とする。
- O5・N3・A4・E3・C1とWon't項目は、この再監査でも未実装のままである。
