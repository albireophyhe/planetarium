# 恒星位置の精度検証と誤差予算

- 対象: Web / macOS の精密モデル v2
- 対応期間: 1900-01-01〜2100-12-31
- 監査基準日: 2026-07-30
- 用途: 肉眼星図、教育、概略的な観察計画、機材設定を比較するための座標転記

## 結論

現在日のように同梱 IERS EOP の範囲内で、表示日時と観測地点を正しく
与え、大気差を無効にした真空中の位置について、計算式そのものの
SOFA 参照値との差は最大数ミリ秒角である。一方、入力する BSC5P 星表は
赤経 0.1 時秒、赤緯 1 秒角の格納分解能で、恒星ごとの共分散や品質注記を
保持していない。このため、アプリ全体としてサブ秒角を保証せず、
通常の恒星に対する真空中の実用上の目安を「おおむね 1〜数秒角級」とする。
これは BSC5P の格納分解能から見た通常目安で、全恒星の実測精度を包む
保証値ではない。大気差を ON にした場合の表示高度にはこの目安を適用しない。

コピーできる参考座標は、座標系と大気差設定を確認した手動導入・機材設定の
比較に使う実験的な補助情報である。無人の自動導入・追尾、掩蔽の成立判定、
測地、航法の唯一の入力には使わない。実際の空での見え方は、入力地点、時計、
大気、地形、機材の据付・同期誤差がこの数値を大きく上回り得る。

`planetarium.precision-pointing.full-v1`／`schemaVersion: 1`のJSONは、
同じ計算snapshotの座標frame・原点・単位、時刻系、EOP、大気差と診断情報を
失わずに転記・比較するためのprofileである。人間向け本文をJSONへ変えても
別の高精度計算は行わず、利用可能な桁や機械可読性は実測精度の保証にならない。
Webは新しい観測日時のEOPを解決するまで直前の整合済みframeを保持し、
macOSは同じ情報を同期更新するため、UTC日境界の取得待ちを収録外の
`DUT1=0秒`・`xp=yp=0`と誤認して一時的な精密JSONへ混ぜない。
共通Schemaは両版のcanonical field集合を必須にし、UTCとJD、DUT1、
time zone、EOP適用値とmetadata、真空／観測座標、大気差、診断flagの
意味関係も検査する。選択星の前後3時間軌跡では、現在点と周辺12点のうち
実際にEOPを0近似した点だけを凡例とCanvas説明へ示す。これらは値の由来と
fallbackを追跡する仕組みであり、位置精度そのものを高める補正ではない。

人間向け本文の地方見かけ恒星時は
`LAST = GAST(UT1, TT) + 入力したWGS84東経`、地心見かけ時角は
`H = LAST − 地心見かけ赤経`（天の西向き正）として示す。これは分点基準の
慣用的なscalarで、極運動を適用する前の値である。現行の真空topocentric
水平座標は、この後にIERS `pom00`相当の極運動と`s′`、WGS84観測者、
日周光行差を適用して計算するため、LASTとHだけから高度・方位を完全には
再構成できない。この追加は既存計算の表示であり、別の精度tierではない。
互換性を保つため、version 1のJSON profileには追加しない。

誤差は赤経成分だけでなく、二つの単位方向 `u`、`v` の球面角

```text
separation = atan2(|u × v|, u · v)
```

で評価する。以下の項は相関し得るため、二乗和を「保証精度」とは扱わない。

## 1. 計算式の SOFA parity

`shared/fixtures/astro-test-vectors.v2.json` は、未改変
IAU SOFA ANSI C 2023-10-11 の `fk52h → starpm` を使った独立 C
参照値を固定している。Sirius / Arcturus / Polaris、1900 / 2026 /
2100、東京 / Greenwich / Sydney の3ケースへ、同じ DUT1 と外部の
太陽系重心速度を与え、年周視差、太陽光偏向、日周光行差、大気差を
無効にして式だけを比較した。

| 比較段階 | 3ケースの実測最大差 |
| --- | ---: |
| FK5→Hipparcos/ICRS と空間運動後 | 0.003831 mas |
| 年周光行差、歳差・章動後の見かけ赤道座標 | 0.003833 mas |
| Greenwich 見かけ恒星時 | 2.5683 mas |
| 真空中の地平座標 | 2.4192 mas |

`starPositionAccuracy.test.ts` はこの実測値に対し、それぞれ
0.005 mas、0.005 mas、2.65 mas、2.5 mas の回帰上限を置く。
極付近でも赤経成分を直接比較しない。

追加の独立監査は次を記録している。

- 正の視差と視線速度を持つ2,984星を1900、J2000、2026、2100年で
  SOFA `fk52h → starpm` と比較した11,936ケースは、空間運動後の最大差
  0.1465 mas。
- 1900〜2100年の2,448日時では、簡略化した分点均差による GAST の
  最大差2.6493 mas、RMS 1.8590 mas。
- 年周視差の外部観測者位置ケースは0.003924 mas。
- 太陽光偏向の独立 `ldsun` fixture は0.000144 µas未満、
  日周光行差の独立 `apio / atioq` fixture は0.0000392 µas以下。

これは「同じ入力を与えた式の一致」であり、星表、既定地球暦、EOP、
観測地点、大気を含むエンドツーエンド保証ではない。

## 2. 入力星表による限界

`shared/catalog/bright-stars.v2.json` は NASA HEASARC BSC5P の
8,404星を J2000.0 FK5 で保持する。取得・変換は
`script/fetch_catalog_v2.mjs`、列規約は BSC5P 原カタログ ReadMe に
固定している。

| 入力 | 格納刻み | 刻みだけから得られる半セル量 |
| --- | ---: | ---: |
| 赤経 | 0.1時秒 = 赤道上1.5秒角 | `0.75 cos(dec)` 秒角 |
| 赤緯 | 1秒角 | 0.5秒角 |
| `pmRA cos(dec)` / `pmDec` | 0.001秒角/年 | 各0.0005秒角/年 |
| 視差 | 0.001秒角 | 0.0005秒角 |

元値が最も近い刻みへ丸められたと仮定した場合に限り、J2000座標の
半セル対角は赤道で

```text
sqrt(0.75² + 0.5²) = 0.9014 arcsec
```

となる。JSON化時の小数10桁ラジアンへの丸めは最大0.0104 masで、
元星表の刻みより十分小さい。

固有運動の格納刻みだけを2026-07-30まで26.57495 Julian年伝播した
二軸半セル対角は

```text
sqrt(2) × 0.0005 × 26.57495 = 0.01879 arcsec
```

である。対応期間端のJ2000から約100年では0.07071秒角となる。
全8,404星に二軸の固有運動があり、2,985星は正の視差を持つ。そのうち
2,984星は視線速度も持ち、残る1星は視線速度0を明示的に仮定する。

ただし、半セル量は測定精度の保証ではない。現行artifactは星ごとの
位置・固有運動の不確かさ、連星・変光・視差品質の注記を保持しない。
3次元運動へ入る2,984星のうち2,107星には、原表で動力学視差、
視線速度品質、変動、分光連星などの注記がある。したがって、内部式が
mas級で一致しても、全恒星を0.9014秒角以内とは主張できない。

## 3. 既定地球暦と補正

既定の年周視差、太陽光偏向、年周光行差は、SOFA `epv00` 1,323項から
決定的に選んだ200項の太陽中心地球状態を使う。未短縮SOFAとの
1900〜2100年・6時間刻み293,656時点の監査は次のとおりである。

| 地球暦監査値 | 最大差 | RMS差 |
| --- | ---: | ---: |
| 地球から太陽への自然方向 | 0.8324427秒角 | 0.1756056秒角 |
| 光行差後の同方向 | 0.8413076秒角 | 0.1757668秒角 |
| 速度ベクトル | 16.4057 m/s | 12.7926 m/s |

0.8413秒角は「全恒星へそのまま加わる位置誤差」ではなく、地球・太陽
geometryの監査値である。恒星の年周光行差へ効く速度差の横成分は
最大0.0111886秒角だった。既定の年周視差は SSB→太陽と地球中心→観測地点
を省略し、最も近い収録星で前者がおおむね8 mas級の誤差源となる。
外部の完全なBCRS観測者位置・速度をAPIへ渡せば、このproxyを置き換えられる。

太陽以外の惑星光偏向、日周・半日周の極運動潮汐は未適用である。
これらは結果metadataにも残す。

## 4. 現在日の EOP 範囲内

同梱IERS EOPは1973-01-02 00:00 UTC〜2027-08-07 00:00 UTCを収録する。
IERS値は2026-07-30まで、2026-07-31以後は予測値である。

監査基準日2026-07-30 00:00 UTC（MJD 61251）は正確な日次IERS sampleで
ある。同梱artifactのmicro単位量子化後にruntimeが使う公表誤差は次の値に
なる。原本が信頼水準と共分散を定義していないため、`1σ`とは呼ばない。

| 成分 | 公表誤差 | 方向への換算 |
| --- | ---: | ---: |
| DUT1 | 0.000010秒 | 0.000150秒角 |
| xp | 0.000090秒角 | 0.000090秒角 |
| yp | 0.000090秒角 | 0.000090秒角 |

DUT1には地球の恒星時回転率15.041067秒角/UT1秒を掛ける。軸方向を
無視した保守的な線形和は

```text
15.041067 × 0.000010 + 0.000090 + 0.000090
  = 0.000330411 arcsec
```

原本のDUT1公表誤差0.0000095秒は、artifactでは最も近い1 µsへ丸めて
0.000010秒となる。同日12:00 UTCは、DUT1の隣接2点最大誤差と極運動の
4点補間`Σ|weight| × error`を使うruntime契約で0.002451748秒角となる。
この補間は翌日の予測sampleを使うため、日次IERS sample間でも
prediction依存と明示される。DUT1の0.5 µsとxp/ypの各0.5 µasという
artifact量子化を同様に足しても0.000009秒角未満である。予測期間末
2027-08-07 00:00 UTCの正確な日次sampleで同じ線形和を取ると
0.432298517秒角である。

一週間前のスナップショット（原本`Last-Modified`
2026-07-23T17:46:35Z）がMJD 61251へ出していた予測値と、今回IERS値に
なった同日の原本値も比較した。絶対残差はDUT1 0.0002678秒
（時角換算0.004028秒角）、xp 0.000706秒角、yp 0.001632秒角で、
軸方向を無視した線形和は0.006366秒角だった。旧予測の公表誤差を同じ
方法で換算した0.013990秒角の範囲内である。成分別ではyp残差が旧公表誤差を
0.000008秒角上回るため、この列を信頼区間や成分ごとの保証値とは扱わない。

したがって現在日は、EOP公表誤差、旧予測の実績残差、式のparity、
既定年周光行差・視差の既知残差はいずれも星表の約1秒角刻みより小さい。
品質注記を欠く古い星表を
含めた製品としては、厳密な合算値ではなく「1〜数秒角級、サブ秒角保証なし」
が妥当である。

## 5. EOP範囲外・読込失敗時

WebとmacOSはEOPを外挿しない。範囲外または検証・読込失敗時は
`DUT1=0秒`、`xp=yp=0`へ戻し、画面とmetadataへ明示する。

- 現行の整数うるう秒UTCが維持され、UTCがUT1との差を約±0.9秒以内に
  保つ期間では、DUT1=0の時角誤差は最大約
  `0.9 × 15.041067 = 13.54秒角`。これは1900〜2100年全域の上限ではない。
- 同梱履歴で監査した大きな極運動ベクトルは
  `xp=0.065407秒角`、`yp=0.596295秒角`、大きさ約0.600秒角である。
  xp/yp=0 fallbackではこの地球固定方向差も省略する。
- 1972年以前は、利用側が与えなければ`TAI−UTC=0秒`近似を使う。
  既知うるう秒期間後は37秒を仮定し、将来値が未確定であることを表示する。

従って現行UTC制度下のEOP範囲外では、星表とは別に時角で約13.5秒角級の
不確かさを持ち得る。1972年以前と将来のUTC制度には別の時刻系近似があり、
この値を上限として使わない。「数秒角級」という現在日の説明も
1900〜2100年全域へ延長しない。

## 6. 画面上の精度表現

WebとmacOSの恒星詳細は、計算桁数を精度保証に見せないため、次を同じ意味で
表示する。

- 同梱EOPの収録範囲内では、BSC5Pの格納分解能と品質注記の欠如を含め、
  真空中の通常目安を「おおむね1〜数秒角級・サブ秒角保証なし」とする。
  全恒星の実測精度を保証する値ではない。
- EOP収録外または読込失敗ではDUT1=0秒・xp/yp=0近似を示し、現行の
  整数うるう秒UTCが維持される期間に限り、DUT1だけで時角へ最大約
  13.5秒角相当を加え得ると条件を付ける。同梱履歴でのxp/ypベクトル最大
  約0.6秒角も併記する。1972年以前はTAI−UTC=0秒、既知うるう秒期間後は
  37秒を仮定するUTC近似であり、13.5秒角を全対応期間の上限にしない。
- 「1〜数秒角級」は星表・真空計算部分の通常目安であり、地点、時計、
  実際の大気との差は別であると示す。大気差ON時の表示高度にも適用しない。
- 座標転記は手動導入・機材設定の比較用の実験的補助情報であり、無人の
  自動導入・追尾、掩蔽の成立判定、測地、航法の唯一の入力へ転用しない
  ことを明示する。
- 人間向け本文とversion付きJSONは同じ固定snapshotを表し、JSONの
  profile ID、schema version、frame、origin、単位、大気差と
  利用不能値の状態が欠落しないことを確認する。JSONの数値桁を別の
  精度tierや保証値として説明しない。

リリース確認では数値の存在だけでなく、現在日と収録外の文言が切り替わり、
星ごとの保証値や根拠のない信頼度として読めないことを確認する。

## 7. 座標変換と描画

- Web 2Dはv2の倍精度地平座標と正距方位図法の値を丸めずCanvasへ渡す。
- Web 3Dは地平単位ベクトルをGPU用`Float32Array`へ格納する。
  高度−90〜+90度、方位0〜359度の1度格子65,160方向で、倍精度方向との
  最大差は0.008985秒角だった。自動テストの回帰上限は0.03秒角である。
- macOSは計算、地平座標、投影、SwiftUI `CGPoint`まで`Double`を使う。
  `RenderedStar`がv2の地平座標・投影値と完全一致するテストを持つ。

ただし画面上の点は秒角分解能ではない。2Dの天球半径を`R` CSS pxとすると、
正距方位図法の半径方向1 pxは概ね

```text
90 degrees / R
```

である。例えば`R=300 px`では18分角/pxであり、星のglyphも複数pxある。
上記の秒角値は計算座標の監査値で、見た目のピクセル分解能ではない。

## 8. 実際の空と合わせるときの支配要因

- 観測地点のずれ`d`は局所鉛直へ概ね`d / R_earth`だけ効く。
  1 kmで約32.4秒角、10 kmで約5.4分角となる。都市presetは都市中心であり、
  利用者の実位置ではない。
- 時計が1秒ずれると時角は約15秒角ずれる。
- 大気差は既定OFFである。標準値、手動値、または明示操作で取得した最寄りアメダス局の
  実測値を選べる。適格な実測を使えない場合だけOpen-Meteoの現在気象モデル値へ
  fallbackする。実測も選択座標そのもののセンサー値ではなく、両者とも星図の日時とは
  自動同期しない。いずれも現地大気の鉛直構造を検証しない。標準大気を下限5度で
  使う場合、境界の補正自体が約9.27分角なので、低高度の実視位置へ秒角精度を
  主張しない。
- 手動大気は実際の条件を記録・比較しやすくする機能であり、入力しただけで
  真空位置や星表の精度が上がる機能ではない。コピーJSONは入力元と5項目を
  残し、真空座標を別値として併記する。
- 地形遮蔽、光害、個々の連星・変光・カタログ更新はモデル外である。
